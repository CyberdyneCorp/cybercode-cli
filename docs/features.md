# Feature reference

Implemented behavior and remaining scope, reviewed on **2026-10-16** (Cross-session messaging, Direct peers and Feature flags on 2026-10-19; Agent teams, Models and Sessions on 2026-10-20; Goals, Loops and budget wording reconciled on 2026-10-22; experimental Project collaboration on 2026-10-24). Start with the [README](../README.md); use the [P1 status](implementation/p1-status.md) and [acceptance audit](implementation/p1-acceptance-audit.md) for detailed evidence.


“Available” describes implemented local-core behavior. “Partial P1” means working pieces exist and the full contract still needs implementation or acceptance.

Migration is available with `cyber import <claude|codex|opencode|auto> [--dry-run] [--yes] [--scope project|global] [--format json]`. It proposes supported permissions, models, providers, MCP servers, hooks, agents, profiles and sandbox settings as a unified diff of the real `cyber.jsonc` bytes, keeping comments, and writes only after confirmation or `--yes`. Existing native keys win; auto fills missing keys in OpenCode, Codex, Claude order. Literal credentials become `{env:NAME}` references named in the report rather than copied values. Every run ends with the mapping report, also saved to `.cyber/import-report-<ts>.md` when files are written. Inserted entries carry `x-imported-from` comments, so a repeated import prints `nothing to do` and a changed source updates only entries nobody edited ([guide](local-core-guide.md#importing-configuration)). JSON reports keep `complete: false`.
