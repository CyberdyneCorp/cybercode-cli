# Dashboard implementation evidence

The first dashboard slice is implemented in [PR #29](https://github.com/CyberdyneCorp/cybercode-cli/pull/29) under `implement-local-web-dashboard`. The final production-browser acceptance run passes all 20 scenarios on macOS with Playwright 1.64.1 / Chromium 156 (exit 0, 2.5 minutes). The implementation commit `81837568` passes all 14 jobs in [CI run 40085669847](https://github.com/CyberdyneCorp/cybercode-cli/actions/runs/40085669847).

Verified locally: browser prompt → real pending permission → approval → completed tool, observed by a second browser and the actual terminal CLI; explicit owner headers, no URL/storage/cookie credentials, hostile transcript content rendered inert, logout/reload authentication, and responsive approval layouts at 360 and 1280 CSS pixels. Workflow pause/resume/stop, Job output/stop, Goal resume/pause/clear, question replies and permission races/retries pass against the real server. A 70-message transcript regression confirms older pages survive refresh and reconnect, with an explicit return to the latest page. The [desktop](../screenshots/web-dashboard-desktop.png) and [mobile](../screenshots/web-dashboard-mobile.png) screenshots contain only isolated fixture data.

Backend checks pass: 70 HTTP integration cases, 10 browser-presence cases, 18 existing request cases, three production-owner WebSocket transport cases (plain, verified TLS and connection limits), TLS path validation and listener-reuse/upgrade binding units. Frontend and browser-fixture typechecks, build freshness and 16 state/transport unit cases pass. SDK generation/typecheck and the final actual-binary suite pass: 118 passed, zero failed, two intentionally skipped on macOS. The account and collaboration-hub fixtures require Linux protected-file fallback to avoid writing the native Keychain; Linux CI remains the positive acceptance gate for those two cases. OpenSpec strict validation passes 87 items; spec lint reports zero errors and 23 warnings. Server all-target Clippy passes after the WebSocket correction. Immutable-checkout CI results: Ubuntu 4,357 passed / 11 configured skips; macOS 4,354 passed / 12 configured skips; Windows 3,171 passed / 456 filtered or configured skips, plus metadata (4), migration (9) and AppContainer isolation (18) cases passed. Frontend checks and all 20 production-browser cases pass in Linux CI. The TypeScript SDK job passes, including the two Linux-only credential-storage fixtures skipped locally. Workspace doctest commands succeed; the 13 crates define no doctests. Local nextest also verified the functional cases; its moving-HEAD version assertion passed after rebuild. These results record the tested implementation commit; documentation follow-ups do not change that code.

The acceptance suite uses the real CLI/server, an isolated home and a scripted local model. It covers approval completion visible in two browsers and a terminal/API observer, questions, request races and uncertainty, reconnect and lease expiry, inert untrusted content, credentials remaining in page memory, mobile/desktop layouts, actual TLS and an SSH-style TCP forward.

Physical access from a second device has not been exercised in this headless development environment. Local TLS and forward tests do not replace that acceptance item. Operator-specific certificate trust on a physical second device remains unverified.
