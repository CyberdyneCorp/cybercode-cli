  - **Dispatch.** `cyber_sandbox::wrap` on Windows builds a `ContainerPlan` (roots, `writable` from the policy, `sandbox.readable_paths`, protected read-only paths, credential and `deny_read` paths, `network` only for `on`) and returns `cyber-sandbox-exec --appcontainer <plan> -- program args`.   - **Helper.** `--appcontainer` decodes the plan strictly, resolves the program (absolute, or `PATH` with `.exe`/`.com`; batch files refused), creates a fresh LPAC identity, grants the existing roots as one forest (overlaps merged, exclusions inside each root, at most 100,000 objects, links and junctions refused) with directory entries inherited by objects created later, grants the program's directory read access unless it is under the Windows or Program Files directories, launches with duplicates of its own standard streams, waits, revokes everything and exits with the command's status. Because timeouts, cancels and host shutdowns terminate the helper with its command, it first sweeps stale grant journals and then records its own (`<plan.journal>/<identity>.json`, `%LOCALAPPDATA%\cyber\sandbox-grants`) before granting; the record goes once cleanup succeeds.
