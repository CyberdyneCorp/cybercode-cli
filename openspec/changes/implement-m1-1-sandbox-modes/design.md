## Context
The existing network proxy supports TCP on macOS and a Unix-socket bridge into Linux's private network namespace. Windows currently fails closed. `Policy::apply_mode` treats unresolved auto requests as ask; there is no evaluator classification. Shift+Tab currently cycles default, accept-edits and plan, excluding auto. The runtime already persists mode changes and applies them at the next Turn.

## Windows boundary
Keep platform enforcement in cyber-sandbox. Use documented Windows APIs for restricted tokens, AppContainer profiles, scoped ACL entries and a job object that terminates descendants. Platform-specific unsafe bindings must remain isolated behind small safe interfaces, with deterministic resource cleanup. Preserve existing owner ACLs, limit newly granted access to the invocation's SID and remove only those grants on cleanup. Grant runtime reads and workspace writes separately; protected configuration and credential directories remain inaccessible. Do not run a weaker sandbox on failure.

Windows command launch needs native argument quoting, handle inheritance, cancellation and shell selection. Audit Unix-only helper, process-group and service-stop assumptions before adding a Windows build job. Avoid claiming an AppContainer is usable until native tests prove allowed writes, blocked outside writes, credential masking, descendant cancellation and default direct-network denial.

## Proxy
Reuse the existing domain decision callback and session approvals. Establish a Windows transport that AppContainer processes can reach without granting direct outbound access. Verify HTTP and CONNECT, denied hosts, approval timeout, cancellation and policy modes. Existing proxy code is the implementation baseline, not a new feature to duplicate.

## Classifier
Add a focused runtime interface for an evaluator request without tools. Snapshot the last 20 messages, Location, invocation and trusted user boundaries without holding session locks during inference. Parse a strict allow/block result with a reason; malformed output, timeout, unavailable models or storage failure must never authorize dispatch. Existing explicit denies and protected/irreversible boundaries remain enforced before classification; a model cannot widen them.

Persist `permission.auto_decided.1` before acting. Track three consecutive blocks per Drain, reset on an allowed decision/new Drain, and fall back to an interactive ask or unattended denial. Account for evaluator usage as hidden work, including any reported usage from malformed replies, timeouts and cancellation. The runtime foundation does not activate classifier approval for built-in tools until the host enforces protected and irreversible boundaries. Tests use scripted adapters for allow, block, malformed responses, exhaustion, fallback and malicious command/history text.

## Mode state
Cycle default → accept-edits → plan → auto → default. Keep bypass and dont-ask outside the cycle. The effective mode for an in-flight Turn stays fixed; show the requested mode as pending until the next Turn. Reuse the existing mode API and durable switch event. Pin the mode in each durable step-start event and retain it through tool settlement, even after inference finishes. Legacy events infer their start-time mode from replay order. Session responses expose effective/pending modes; idle sessions use the selected mode. Serialize TUI mode writes and coalesce unsent choices to the latest selection, retaining the server-confirmed value on failure and ignoring stale or previous-session responses. Bypass selection through the command or picker requires a separate explicit confirmation. Org-policy disabling remains separate unfinished enforcement.

## Phase boundary
P0's incomplete local quality/long-task evidence is not waived by this proposal. P1 implementation is explicitly authorized while P0 validation continues. M1.1 implementation and P0 exit evidence are tracked independently; completing P1 code does not waive the remaining P0 gate.

## Critical-removal boundary

Critical-removal analysis runs before automatic rule and saved-approval effects. Explicit denies and plan restrictions remain final. Bash analysis must inspect syntax nodes, including nested `sh -c`/`bash -c` and `eval`, rather than search arbitrary quoted text. Literal targets are normalized and checked against Location, checkout, home, filesystem root and Location ancestors; canonical aliases cannot hide these roots. A removal whose target or shell context cannot be resolved requires manual approval and cannot be authorized by auto, dont-ask or bypass. Manual prompts carry a red warning and remain mandatory even after an always reply.

Deliver Bash coverage first, then native PowerShell and Python/JavaScript inline-script coverage. The latter are still required by M1.1; Bash-only coverage does not close the requirement or enable classifier dispatch.

### Shell stdin analysis

Treat heredocs and here-strings as source only when a recognized shell consumes stdin, directly or through a supported wrapper/pipeline. Shell `-c` or a named script normally consumes its command source separately. Expanded heredocs may inject syntax before the receiving shell parses them, so unresolved expansion cannot receive automatic approval. Dynamic command names also remain unresolved until binding analysis can establish the command. These rules follow the [Bash invocation and redirection contracts](https://www.gnu.org/software/bash/manual/bash.html); quoted data sent to ordinary commands is not recursively interpreted as code. Full shell control flow and stream transformations remain separate unfinished coverage.

### Scoped literal bindings

Track literal scalar assignments in an explicit shell state. Resolve quoted expansions as one operand; unquoted values that can split or glob remain unresolved. Scope substitutions and subshells independently. Inspect function bodies at invocation with current globals, preserving possible definitions from uncertain branches. Unknown branch/loop effects, arrays and arithmetic invalidate bindings. Argument expansion precedes temporary inline environment assignments; child-shell/function/eval source uses its execution context. Decoded scalar words are limited to 64 KiB, and all cloned/nested scopes share a 20,000-node analysis budget. Exhaustion remains unresolved rather than authorizing dispatch. Alias, trap and sourced state remain unresolved until their semantics are analyzed. These conservative boundaries keep classifier dispatch disabled while full shell and inline-language coverage is unfinished.

### Accept-edits filesystem command proof

Do not infer an edit from a command's whitespace prefix or generic lexical mutation paths. Automatic filesystem approval requires an entire simple-command/list syntax tree with literal operands and known option semantics. Assignments, expansions, redirections, substitutions, wrappers, functions and unknown options retain ordinary approval handling. Resolve existing symlinks before parent traversal, retain protected-path checks, and require every proven operand to be inside the Location. Nonrecursive rm accepts known flags and an option delimiter; recursive flags remain ordinary asks. This deliberately conservative proof is separate from the general Bash permission resource splitter and does not widen explicit rules or saved approvals.

### Inline-language removal guards

Decode Python `-c` and JavaScript eval source from the Bash AST, then parse with the corresponding tree-sitter grammar. Inspect calls rather than quoted data. Resolve literal strings, bounded scalar bindings and import/require aliases; apply the shared path/symlink/root boundary. Inline exec/eval or shell subprocess calls recurse with the shared node and nesting budget. Dynamic targets, indirect dispatch, unknown calls and unresolved invocation options require confirmation until their semantics are implemented. Branches, functions and directory changes must not preserve an unjustified literal binding. This increment does not prove arbitrary scripts, PowerShell, stdin forwarding or all interpreter option semantics, and classifier allows remain disconnected.

The path proof follows [Python removal API semantics](https://docs.python.org/3/library/os.html#os.removedirs), including implicit parent removal by `removedirs`, and [Node's path API](https://nodejs.org/api/path.html#pathjoinpaths), where joining an absolute segment does not reset the preceding path. A trusted-looking builtin name cannot regain proof after uncertain branch/eval shadowing. Source is limited to 1 MiB, scalar expressions to 64 KiB, AST nesting to 128 and expression/name recursion to 16, in addition to the shared shell node/interpreter-nesting limits. These bounds refuse unresolved analysis rather than allowing dispatch.

### PowerShell command-source guards

Register the native `powershell` tool only on Windows and advertise it when an installed interpreter can be resolved. Resolve an absolute `pwsh.exe` before falling back to `powershell.exe`, excluding relative PATH entries and the checkout from interpreter discovery. Encode the original source verbatim as Base64 UTF-16LE with `-NoProfile -NoLogo -NonInteractive -OutputFormat Text`; do not concatenate it into a shell command or add source wrappers. Use PowerShell's Windows `USERPROFILE` home binding while retaining checks for the configured home. Reuse foreground capture, timeout/cancellation and the parent-owned process interface. Permission action remains `bash`, and plan/tool-deny filtering and output-tail budgeting apply to both shell tools. Native runtime, legacy encoding and complete mutation facts must be verified separately before accepting the complete tool contract. The source encoding and home binding follow Microsoft's [invocation](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_pwsh) and [automatic-variable](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_automatic_variables#home) contracts.

Native PowerShell dispatch needs PowerShell-native permission resources, not a Bash parse of its source. Collect simple command nodes during the same bounded AST traversal that evaluates removal risks and binding/cwd uncertainty. Preserve each command's actual source text, never split printed strings into commands, and offer arity patterns only for literal command names. Known literal filesystem operands and redirection targets feed external-directory/protected-path checks; value arguments and common-parameter values are not paths. Unresolved bindings, providers, parameter abbreviations and advanced mutation semantics remain unfinished facts and cannot enable classifier approval. Add cross-platform parser tests before native tool registration and Windows runtime verification.

Recognize `powershell`/`pwsh` executables in Bash inline invocations and parse literal command source with a PowerShell grammar. Inspect command and member-call nodes rather than text inside output strings or comments. Handle case-insensitive removal names, standard aliases, module-qualified cmdlets and literal `Path`/`LiteralPath` targets using the shared critical-root proof. Unknown options, dynamic source, glob/provider paths, indirect dispatch and unsupported PowerShell state must retain mandatory confirmation; profile loading cannot gain automatic approval. Keep parsing and scalar evaluation bounded by the shared analysis budget. Windows-native PowerShell dispatch, advanced bindings, encoded/stdin source and protected/irreversible mutation facts remain required before the complete guard contract or classifier approval is enabled.

Decode documented encoded-command flags as strict bounded Base64 UTF-16LE before AST analysis. Malformed Base64, odd byte counts, invalid surrogate sequences and duplicate source options remain unresolved. Preserve parameter ordering: command strings consume their remaining words as source, while encoded-command invocations can still carry startup flags. Dispatch literal stdin to the selected interpreter grammar for `-Command -` and `-File -`, retaining profile and cwd uncertainty. Interpret forwarded heredoc/here-string bytes only when their producer and downstream path prove that source; upstream consumers and ordinary output data must not be recursively interpreted. These rules follow Microsoft's [PowerShell invocation contract](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_pwsh).

### Native Windows compilation gate

Run workspace and test compilation on a native Windows runner before adding enforcement. Build the executables and smoke-test the CLI on the same runner. Unix-only network bridging must be compile-gated; its non-Unix entry point must refuse to execute a requested command rather than provide an unconfined fallback. The build/smoke job does not prove restricted-token, AppContainer, ACL, proxy-only networking or process-tree cleanup, and `available()` remains false until those native enforcement requirements are implemented and proven.

### Windows listener lifecycle

Represent the Unix listener path as an optional platform transport. Windows defaults to TCP and advertises `socket: null`; explicit Unix socket or socket-only flags fail before startup. Cleanup only touches a socket actually selected for a supported Unix listener. Run the registration/health, exclusive ownership and notified-shutdown test on Windows as well as Unix; Windows-specific tests retain pre-existing socket-path files and reject unsupported listener flags without a readiness event. This does not implement `service stop` or restricted-token execution; those remain separate native lifecycle requirements.

### Windows process-tree owner

Foreground shell execution now goes through a platform process owner: Unix retains its process group, and Windows uses `OwnedCommand`/`OwnedChild`. Windows full-access mode retains this lifetime boundary, with no direct-spawn fallback when the helper is absent. Configured Unix-shell executables with case-insensitive `.exe` suffixes are accepted on Windows; helper discovery uses `cyber-sandbox-exec.exe`. Host-level native tests select the installed Git Bash explicitly and retain live child/grandchild identities before timeout, cancellation or normal exit. These tests exercise ownership while default confinement still refuses execution; native PowerShell advertisement, dispatch and AppContainer enforcement remain separate required work.

The stable-toolchain interface uses a trusted-helper handshake. `OwnedCommand` creates an unnamed non-inheritable kill-on-close job, starts `cyber-sandbox-exec --parent-job -- program args` with private piped stdin, assigns its retained process handle, and only then sends the fixed launch permit. The helper refuses EOF or invalid permits before touching the user command. Parent death before assignment closes the pipe; after assignment it closes the sole outer job handle. The helper retains its separate inner job for normal-exit cleanup and gives the user process null stdin, keeping the permit channel private. `OwnedChild` retains outer job ownership across awaits and closes it on termination, wait settlement or Drop, including aborted futures. This interface manages process lifetime only; it does not enable Windows sandbox availability or native tool dispatch.

Built-in dispatch requires the server to own the non-inheritable job handle: a helper that owns its own job can survive server death. Assignment must precede user-code execution and must not leave an orphan if the server dies during launch. The conventional suspended-spawn/assign/resume sequence has a crash window before assignment. Prefer atomic `PROC_THREAD_ATTRIBUTE_JOB_LIST` creation, or a trusted helper handshake that refuses user-code execution when its parent channel closes before assignment. Rust's `CommandExt::spawn_with_attributes` remains unstable, so it cannot be assumed available on the project's stable/MSRV toolchain. Native tests must kill the actual parent and retain child identities, in addition to testing timeout, cancellation, normal exit and setup failure. This follows Microsoft's [atomic job assignment guidance](https://devblogs.microsoft.com/oldnewthing/20230209-00/?p=107812/) and Rust's [Windows process API](https://doc.rust-lang.org/std/os/windows/process/trait.CommandExt.html#tymethod.spawn_with_attributes). The standalone helper tests do not establish these dispatch properties.

Add a separate Windows-only helper invocation, `--job -- program args`, before wiring native tool dispatch. Create an unnamed, non-inheritable job with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` and no breakaway flags; assign the helper itself before creating any command. Its descendants inherit job membership without a spawn/assignment race. Hold the only job handle until process exit, including command launch failures, and preserve the command's exit code. Setup failures must refuse execution. Native tests must verify both forced helper termination and ordinary command exit terminate a live grandchild. This follows Microsoft's [job-object lifetime contract](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects) and [non-inheritable handle default](https://learn.microsoft.com/en-us/windows/win32/api/jobapi2/nf-jobapi2-createjobobjectw). The helper is process lifecycle management, not AppContainer confinement; availability and built-in Windows dispatch remain disabled until their separate requirements are implemented and proven.

### Registration-bound service shutdown

Replace external `kill <pid>` dispatch with `POST /api/v1/service/stop`, carrying the expected server registration ID. The route uses the normal transport authentication and Origin guard, rejects mismatched IDs, and is available only when its application owns listeners. The listener owner supplies its existing shutdown notification; embedded applications have no listener control. The client disables redirects and ambient proxies, validates the acknowledgement ID, and waits for conditional unregistration. Unix socket-only service requests retain peer credential authentication. Failed authentication, identity checks and unreachable endpoints preserve registration instead of claiming that an unchecked PID disappeared. Password replacement stops the registered server with its existing credentials before writing the new password, then restarts through the existing service-start path. Refusal preserves credentials and registration. Active inference, stream closure and bounded shutdown still require separate lifecycle proof.

Runtime shutdown closes admission using a shared lifecycle gate and cancellation signal, prevents coalesced follow-up drains, and joins every drain's durable settlement. Side-effecting cancellation remains outcome unknown. Background title generation is tracked, cancelled and joined; blocked provider startup, streaming and compaction can observe cancellation. In-memory approval waiters are cleared after calls settle, while durable queued rows are preserved for restart. Stop retention before runtime settlement. HTTP stream and WebSocket closure remain separate required work; this runtime boundary alone does not establish the complete service deadline.

HTTP event-stream producers are scoped to both runtime closure and receiver disconnection, including replay and blocked sends. The response body independently observes runtime closure, so buffered or idle streams cannot retain the HTTP connection during graceful shutdown. WebSocket connections track their request tasks in a join set, abort and join them on disconnect/shutdown, and drop the RPC session to release subscriptions and channel-owned tool registrations. The writer observes shutdown even while sending and bounds its close-frame write to one second. A real server regression opens both event streams and a registered WebSocket tool before requesting authenticated service stop; it first fails against unchanged main at `4868aa5`. Snapshot/compaction interruption, active native tools and backpressured-client deadline proof remain separate required evidence.

Drain snapshot work is optional and cancellable at both turn boundaries. The provider/tool turn still owns durable settlement; only pre-turn tracking and post-turn snapshot, changed-path and diff collection are dropped on cancellation. The four-stage blocking regression fails against unchanged main at `e8dda31`, then passes after the change without recording a completed post-turn snapshot. This does not prove native Git process cleanup or the complete service deadline.

Compaction shutdown evidence covers idle/manual requests and each drain entry path (queued manual, automatic and overflow), with summary opening and streaming blocked separately. Existing runtime cancellation passes these eight cases while preserving conversation entries and avoiding completed summaries. This is a runtime contract test, not proof of native Git child cleanup or the complete service deadline.

The native service fixture exercises the production built-in foreground shell host and listener owner with a scripted inference resolver. It retains live child/grandchild handles before authenticated stop, checks complete service latency and rereads the database settlement from a fresh runtime cache. PowerShell receives individual approval; failure cleanup terminates only retained worker identities. It does not replace native AppContainer filesystem/network isolation proof. Compilation and execution must pass the dedicated Windows CI step before this evidence is accepted.
