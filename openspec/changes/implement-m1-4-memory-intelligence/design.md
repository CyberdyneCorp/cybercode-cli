## Memory foundation

Pure core types validate required YAML fields and kebab-case names, one-line descriptions, known memory types and nonempty content. Feedback/project notes require nonempty Why and How to apply lines. Parse diagnostics do not echo supplied text. Write validation scans the entire input, including frontmatter, for credential patterns, private keys and high-entropy strings longer than 32 characters. Parsing an existing document remains distinct from admitting a write.

Index rendering sorts unique validated names, uses local Markdown filenames and escapes link labels/descriptions. Duplicate names are refused at this layer; storage will replace matching names before rendering. Index loading keeps the first 200 lines or 25,000 UTF-8 bytes, whichever is smaller, and adds the canonical truncation notice. Typed settings default enabled/generate to true; the existing EnvSource flag semantics implement CYBER_DISABLE_MEMORY. Project IDs are validated as safe components before deriving data/memory paths.

The document increment has no runtime entry point. The read-side storage increment uses cap-std directory handles and cap-fs-ext no-follow directory/file opens, private Unix creation and descriptor-based permissions, bounded note/catalog reads and independent OS file-lock scope claims. Existing review creates no directories; claiming a scope explicitly creates its lock file. Index reads consume at most 25,004 bytes to determine the canonical 25,000-byte/200-line UTF-8 prefix without reading note bodies. Any pending .memory-transaction entry fences reads and retains evidence; no transaction is automatically adopted as a live owner. Read-side limits are 1 MiB per note, 4 MiB of catalog metadata and 4096 directory entries, with explicit refusal rather than partial success. Windows file/directory ACL privacy and full native acceptance remain open. Journal creation and explicit Unix note/index mutation recovery now use the protocol below. Automatic reconciliation, reviewed conflict resolution, Windows mutation support and runtime integration remain required. Tools, HTTP, CLI/TUI and Context Source reconciliation must use the same validation and storage owner. Read-only generation and disabled memory must be enforced at dispatch, not only in model instructions.

## Journaled Unix mutation protocol

A mutable scope guard admits a prepared mutation only after bounded write validation, filtered catalog construction and before-state fingerprints. A private .memory-transaction directory holds synced desired note/index files and an immutable versioned intent. Pending preparations fence ordinary reads. Commit first archives the original target within the transaction, verifies its fingerprint, then installs staged data with a create-only hard link; recovery normalizes only an exact same-inode/hash two-link staging pair. It verifies other valid note fingerprints, target/index after states and archived before states before acknowledging completion. Conflicting files are preserved and keep the scope fenced. Completed transactions move into private .memory-history/<id>/ so archived original inodes remain named even for a late editor write. Directory/file syncing and all namespace operations retain directory-bound authority. Unknown preparations or incomplete manifests are not replayed. Windows mutation admission remains refused until ACL privacy and durability are integrated; full platform acceptance remains required.

On Linux, capability directory handles use O_PATH and cannot perform fchmod or fsync. Permission changes and durability barriers therefore open a readable dot-directory handle relative to the retained capability, with no-follow semantics and directory verification. The regression retains the original directory after namespace replacement and verifies permissions and syncing affect that inode. A native Linux result is required in addition to local macOS evidence.

### Explicit storage recovery review
Expose read-only inspection and fingerprint-bound recovery in the shared core. Bind the scope and journal directory identities, intent, all known transaction artifacts, current note/index and catalog fingerprints. Validate desired content and preflight slots without normalizing links. Unsafe partial link states remain refused by this review interface pending dedicated alias review. Recapture before effects; acknowledgement uses the existing durable commit boundary. This does not reconcile database admission owners or enable automatic recovery.

### Local CLI recovery controls
`memory recovery` prints read-only review, including proposed note content and the fingerprint, with null for absent evidence. `memory recover --review` validates a SHA-256 fingerprint and repeats settings under the scope claim. Before file effects it checks an existing database through read-only SQLite for pending scope admissions, refusing unresolved ownership or unverifiable inspection; no database is created. In-memory databases cannot prove ownership absence and refuse. This prevents file-only recovery from releasing a journal fence belonging to a durable unknown request. Database reconciliation remains a separate required control.

### Admission-to-journal binding
Before installation, persist an owner-authorized memory.mutation.journal_bound.1 event containing the exact core transaction receipt and a SHA-256 digest of the complete validated intent (before/after note/index hashes and catalog). Completion of new writes requires that bound receipt at the next sequence. Historical completion projection retains its original unbound sequence for event replay only; new live owners cannot complete unbound writes. This is evidence for later fresh reviewed reconciliation, not recovery authority; legacy pending admissions remain unproven.

Journal binding rotates the admission nonce atomically in its projector. The binding event reveals only the superseded nonce and the new nonce hash; the new live key remains solely with the retained owner. Thus stored binding evidence cannot authorize completion after owner loss.

### Fresh reviewed reconciliation in the runtime
Join admission and aggregate sequence into one database review, binding request/result/sequence and the exact physical journal identity. Require a fresh current-state storage review under the retained scope claim before durable takeover. A reviewed recovery event compares database fingerprint and original owner hash atomically, records the matching journal and a newly minted owner hash, and advances the recovery sequence. No persisted nonce is reused. Completion projects against that sequence and exact receipt. Already acknowledged matching journals return their original change and finish archival without another event. Unbound historical pending requests remain refused until a separate explicit legacy resolution contract is implemented. HTTP/CLI/TUI authorization and lifecycle gates must surround this runtime interface when exposed to users.
