## Context

Project executable configuration is currently withheld until checkout trust is approved. Configuration merges and validates before building runtime consumers. Hooks have a canonical target specification but no execution implementation.

## Decisions

- Start with one typed hook configuration model shared by validation and future execution. Validate known events, four P1 handler types, required handler fields, timeout/control types and selector syntax. Configuration validation performs no effects.
- Keep untrusted project/local definitions withheld before interpretation. Checkout trust is not a substitute for the required individual handler-digest approvals.
- Store handler approvals separately from workspace configuration approvals in the same private trust file. Hash canonical effective handler definitions (including defaults and all execution options); invocation approvals retain only inspected digests in memory. Serialize all shared-file mutations with a native sidecar lock, and checkout revocation clears both approval classes. Runtime dispatch must still recheck trust before effects.
- Add ordered scope contributions with per-definition provenance before dispatch; ordinary last-value replacement must not discard earlier hooks.
- Accumulate event arrays inside named profiles as well as top-level hooks. On profile selection, remap indexed hook origins into their new appended positions; ordinary profile settings retain their existing profile labels. Source paths remain necessary for later scope classification and individual handler trust.
- Runtime admission owns prompt hooks; the tool host owns tool hooks and revalidation. Permission denies and protected ceilings remain independent of hook allows. Every execution needs a durable receipt and cancellation owner.
- Construct immutable envelopes from the owning runtime's captured Session/Location/agent/Mode identity and Unix-millisecond timestamp. Event-specific data cannot replace any common envelope field. Chained tool rewrites clone only tool input, preserving identity; core shape validation is not proof of runtime authority or ownership.
- Compile selectors at catalog construction and keep matching side-effect free. Decision parsing reports ignored fields separately for later debug logging. Declared-order merging retains restrictive decisions, rewrite/context accumulation and stop flags; the future dispatcher must feed each rewritten input to the next handler and the tool host must revalidate it before effects.
- Implement process-tree ownership, sandbox selection and bounded IO before command execution. HTTP, evaluator and MCP handlers share the event and decision model while retaining their own authentication and usage boundaries.
- Command transport accepts an already authorized process under the caller's retained execution owner. Feed JSON stdin and drain stdout/stderr concurrently, retaining at most 1 MiB per output stream while draining overflow. Explicit stop attempts terminate the owned tree and wait at most two seconds for acknowledgement; missing acknowledgement remains explicit. The stdin-preserving container adapter is separate from shell tools' EOF adapter. Capture remains transient and is not automatically persisted; runtime receipts must honor hook IO logging policy.
- Command launch resolves the requested handler from loaded provenance again, binds the event Location to the resolved checkout, and rechecks durable checkout and individual approvals before effects. Required hook sandboxing always uses workspace-write enforcement even if ordinary tools have explicit full access. The noninteractive command runner uses the network allowlist without granting unknown domains; interactive network decisions remain a runtime integration requirement. Per-command private scratch is retained after unacknowledged settlement or caller disposal. Windows ordinary full-access launch uses an explicit parent-job event-stdin route: assign the helper before writing the private permit, consume that prefix without buffered read-ahead, then retain the pipe for event bytes and EOF. PowerShell source uses the existing encoded-command argument builder. Required Windows confinement still refuses through sandbox selection until its native hook launch route is integrated.
- Hook receipts use independent execution aggregates so terminal recording cannot race the Session state cache. Admission and its SQL projection commit through the existing single writer with captured Session/ancestor fences. An opaque execution owner records settlement once; owner disposal records explicit unknown/error evidence, and a missing receipt never authorizes replay. IO logging is pinned at admission and raw buffers are omitted unless enabled. Recorded command runs reserve tracked native activity, reverify its authority and persist a launch marker before spawn. Runtime subtree cancellation reaches the process owner and waits for acknowledged native settlement; disposal after the marker preserves unknown activity alongside the hook receipt. Terminal receipts remain admissible after scope closure; dispatch still must verify the owner authority before effects and before applying decisions. Cross-process recovery and full client observability remain separate acceptance requirements.
- Attach a full provenance-preserving configuration resolver to the built-in host at application construction. Built-in command PreToolUse runs before permission evaluation; chained rewrites are revalidated against the tool schema and exact replay approval. Hook allow skips only remaining asks after deny rules and hard Mode ceilings. Command success/failure post events retain the invocation identity and final input. Remaining handler types, optional scheduling/context/continuation fields, remote-tool hooks and all other lifecycle events remain required. Unsupported effectful handler options are reported without launching them until their owner semantics are implemented.
- Deliver the remaining lifecycle events, trust/viewer/test CLI, plugin process protocol/package and MCP OAuth/search as subsequent increments under this same change.

## Validation

Real configuration-loading tests cover rejection paths, all four handler definitions, defaults, invalid selectors, trust withholding and changed definitions. Later increments require actual dispatch/side effects, denial/rewrite/merge semantics, durability, client surfaces and native ownership/cancellation evidence. Passing configuration tests alone cannot accept hooks or M1.3.

- Pin the command handler's `once` flag in its durable receipt. A partial unique index on Session/effective digest and a writer-side claim check make admission exclusive across runtimes. Completed and unknown receipts retain the claim; pre-launch failures also consume an admitted attempt, preserving at-most-once behavior without unsafe crash replay. Legacy receipts default to `once: false`. Unrecorded command launches refuse once handlers. Status/system messages use the existing transient user-notice channel after admission and acknowledged settlement, without model-context or raw-IO persistence.

- Run command PermissionRequest at the built-in `Ctx::ask` boundary after ordinary permission and Mode checks. Supply the current ask alongside final invocation input. An explicit pre-hook ask still checks current/ancestor auto blocks before this boundary. Box the request-dispatch future to bound stack usage in nested tool/setup callbacks. A hook allow answers only this request, without a saved approval, and deny fails before publishing the pending prompt. Event-aware parsing ignores input rewrites here; PermissionDenied retry remains separate work.

- PermissionRequest and post-tool events have immutable input after event-aware decision parsing. Run their matching command handlers concurrently up to the configured per-event limit, retain declared-order decision merging and deduplicate supported commands once per event. On a fail-closed error or mandatory stop, cancel event siblings and drain every launched owner before returning the original refusal. PreToolUse remains ordered to preserve rewrite-dependent selection/input; a scheduling model that satisfies both chained rewrites and the complete concurrency contract remains required.

- Expose durable hook receipts through authenticated GET `/sessions/{sessionID}/hook-executions` and generated `session.hooks`. Cursor pagination uses immutable admission time/id and binds the cursor to its Session. Preserve default IO omission and explicit opt-in IO; public running/unknown states are observations, not proof of a live process or authorization to replay. Recovery reconciliation and transcript/TUI review remain required.

- CLI execution history shares the store-level Session receipt page reader with Runtime/API access. It validates Session existence and reads committed rows without constructing Runtime actors or reconciling native owners. Configuration parsing/trust is unnecessary for this observation path. JSON preserves pinned IO policy and cursors; text uses escaped identities and explicit unresolved-state wording without raw IO.

- TUI `/hooks history` loads one 50-row receipt page through the public authenticated API. Session/generation/overlay guards reject obsolete responses after refresh, dismissal or thread switches; next cursors are query encoded. The view model discards raw IO and escapes control characters. Recorded running and unknown labels do not establish live process state or permit replay. Definition review/trust remains a separate delivery requirement.

- The Location-scoped GET `/hooks` catalog uses the host’s full provenance-aware resolver and re-reads individual approvals for every request. The shared typed core review captures original digests before redacting handler headers/secret fields; withheld checkout paths remain separate metadata. Inspection admits no Session, hook or inference work. The generated SDK retains its Located response envelope. Approval writes, withheld raw review and the TUI definition/trust viewer remain separate requirements.

- The TUI definition viewer uses public Location-scoped catalog and exact-digest trust APIs. Store only redacted handler metadata; separate selection from detail scrolling. Freeze selection during explicit approval/revocation confirmation, reload after writes and gate results by Session, Location and request generation. Snapshot and live worktree-rebound paths invalidate review before adopting a new Location. Withheld executable definitions remain uninterpreted; their raw review and synthetic testing need separate delivery.

- Raw withheld review reuses project layer discovery and assesses trust on the same parsed layer set. Extract original top-level and profile hook sections, preserving source paths and escaped pointers; redact credentials without substitution or handler schema/selector compilation. Raw sections are distinct from executable definitions, have no handler approval digest and cannot use individual trust controls. App catalog assembly, CLI and TUI share this literal data contract; approval still requires full current trusted resolution.

- Last-run review uses a shared committed-store reader keyed by effective handler digest, event, scope and current canonical checkout root. Use captured execution Locations rather than mutable Session directories and sort by admission timestamp then receipt id; newer unresolved observations remain visible. Remove IO and decision fields in the SQL projection before decoding summary metadata. Review never reconstructs execution owners. CLI list opens only an existing local database and does not construct Runtime or create a database for empty history. Historical paths whose checkout can no longer be resolved are not assigned to a different current checkout; this is observation correlation, not native liveness or checkout-incarnation verification.

- Synthetic runs retain canonical `hook.started.1`/`hook.executed.1` facts but explicitly mark synthetic identity and project into `hook_test_execution`, which has no Session foreign key. Recording owns no Session activity or model work and does not authorize native effects. At writer admission, require empty Session bindings and refuse aliases of existing Sessions. Preserve ordinary Session receipt serialization via a default-false, omitted synthetic flag. Share identity/IO settlement validation across both projections, keep test once claims local to the synthetic invocation identity, and mark owner disposal unknown without IO. CLI event construction, actual scheduling/launch/cancellation and managed-checkout ownership are subsequent required work.
- Construct synthetic envelopes through `HookEvent::synthetic` using trusted test Location/project/agent/Mode and an object of event-specific payload fields. Generate a fresh `ses_` protocol identity without creating a Session; retain it when cloning/chaining the event. Reserve the synthetic marker alongside all common envelope fields, so payload files and ordinary event construction cannot forge test identity. Shape validation grants no execution authority; the separate writer projection still rejects forged real-Session aliases.
- Synthetic command execution uses the existing trust/provenance/sandbox preparation and owned stream capture, with an internal admission variant available only after durable synthetic admission. A standalone `BuiltinHost` shares native Git verification and managed ancestor checkout claims with ordinary Session ownership; it does not require Runtime construction. Each synthetic receipt claims checkout activity under `ses_<receipt-id>` so concurrent handlers sharing an invocation identity do not reuse an exclusive native lock. Retain acknowledged checkout settlement through the terminal receipt commit; unknown or dropped execution retains checkout/scratch recovery evidence. A typed optional synthetic admission result distinguishes an already-claimed once handler from errors, preserving atomic writer claims and the unique-index backstop. Owned command receipts capture bounded UTF-8-safe stdin/stdout/stderr only when the admission-pinned IO policy opts in; ordinary and synthetic runs share this capture path. CLI scheduling, all other transports and native platform acceptance remain required.
