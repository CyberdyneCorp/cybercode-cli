## 2. Context and compaction

- [x] 2.1 Context assembly from the active path; epoch summaries reused only for ancestor prefixes; test that a sibling's summary never reaches the model. Done: the model view is built from `entries` (the active path). Every compaction summary is kept in the `BranchTree` with the last message it replaced (forks keep the one they were created with); after a rewind or checkout the summary covering the longest ancestor prefix of the active path is reused (newest on a tie) at a recomputed tail, and with none the path's stored messages are sent (normal auto-compaction applies). A summary request on a branch merges only that path's summary. Tests: `branches_tests.rs` `a_summary_is_reused_only_on_the_path_it_replaced`, `the_summary_of_the_longest_ancestor_prefix_wins`; `crates/cyber-app/tests/branches.rs` `a_sibling_summary_never_reaches_the_model` (HTTP compact and rewind, model requests for Turns and summaries, checkout both ways, restart replay).

## 3. Surfaces

- [x] 3.1 Routes `GET .../tree`, `POST .../checkout`, `PUT|DELETE .../labels/:name`, `GET .../messages?branches=all`; OpenAPI and regenerated SDK. Done: `http/branches.rs`; tree nodes from `runtime/branch_nodes.rs` (user messages only, linked to the nearest user message; a label on a reply shows on its user message; the active path's last user message is a tip). Every message carries `parent_message_id` (additive; the default list is still the active path), and `branches=all` lists every branch in creation order with the stashed calls. A checkout's response adds `restored_files`, and its diff compares the baseline with the restored working tree, so kept user edits are not shown as reverted. Tests: `crates/cyber-app/tests/branches.rs` `branch_routes_serve_the_tree_labels_checkout_and_every_branch` and the HTTP `--code` checkout in `checkout_with_code_restores_the_branch_snapshot_and_keeps_user_edits`; `branches_tests.rs` `tree_nodes_show_user_messages_with_labels_and_tips`; the tree and `branches=all` resolve messages through one index (and stashed calls by their message), so `a_long_session_tree_is_built_in_linear_time` bounds a 40,000-message tree.
