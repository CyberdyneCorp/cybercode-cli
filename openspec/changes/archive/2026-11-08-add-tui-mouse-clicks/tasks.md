## 1. Hit map and click model

- [x] 1.1 Add `Hits`, `Target`, `List`, `Act`, `Pane` and `Mouse` to `mouse.rs`, and add the `App::mouse` field. `view::draw` clears the hits each frame, and `Mouse::modal(rect)` drops the hits under a modal and adds `Inside`. `on_mouse` takes the topmost hit at the pointer, and only for an unmodified left press while `mouse_capture()` is on and screen-reader mode is off. With `tui.mouse: off`, `on_mouse` handles no event at all, the wheel included. Keep every wheel test from PR #25. (`mouse::tests::clicks_need_capture_a_left_press_and_no_modifier`, `mouse::tests::mouse_off_leaves_the_mouse_to_the_terminal`, `mouse::tests::the_topmost_hit_wins`.)
- [x] 1.2 Arming and double clicks. A `Row` press selects and arms the row through `App::select_row`, and a press on the armed row presses Enter. A control's second press on the same target within 500 ms of `App::now()` is absorbed. `App::on_key` disarms, and a change of overlay or pending request disarms. Stale lists and out-of-range indices do nothing. (`mouse::tests::a_second_click_activates_and_a_key_disarms`, `mouse::tests::a_double_click_on_a_control_acts_once`, with a stepped `App::clock`.)
- [x] 1.6 A row press also records the selected item (`App::selected_item`), and the second press activates only on the same item, so a list reloaded or a picker replaced between the clicks only re-arms. A control press at the same cell within 500 ms is absorbed too. Lists keep their scroll window (`Mouse::window`) until the selection leaves it, so a clicked row stays under the pointer. (`mouse::tests::a_list_that_reloads_between_the_clicks_only_rearms`, `mouse::tests::an_armed_row_does_not_carry_over_to_another_picker`, `mouse::tests::a_list_window_stays_until_the_selection_leaves_it`, `screens_mouse::a_row_above_the_selection_of_a_scrolled_list_activates_on_a_second_click`, `screens_explorer::a_double_click_in_a_scrolled_tree_unfolds_only_the_clicked_directory`.)
- [x] 1.7 Review fixes. A press within 500 ms of the previous one in another context is absorbed as the tail of a multi-click and never arms, so a triple click on an `ask` file never answers the prompt it raised. A click on a row drawn over the transcript or composer leaves the sidebar first. (`mouse::tests::the_tail_of_a_multi_click_never_answers_the_prompt_it_raised`, `screens_explorer::a_triple_click_on_an_ask_file_never_answers_the_prompt_it_raised`, `mouse::tests::a_row_drawn_on_the_transcript_takes_focus_back_from_the_sidebar`, `screens_mouse::a_collapsed_row_click_takes_focus_back_from_the_sidebar_and_expands`.)
- [x] 1.3 Modals and confirmations. Pickers, the palette, the switcher, prompts, help, side chat, rename, login, task log, file diff, findings and the confirm overlays call `modal`. Confirmations, `ConfirmAlways`, `Feedback` and the blocked-call approval register no targets. (`screens_mouse::a_click_outside_the_palette_leaves_it_open`, `screens_mouse::confirmations_take_no_clicks`.)
- [x] 1.4 Permission and question prompts. Option rows are `Row { act: Second }`, and the context includes the request ID. Test against a production App fed by the scripted local server: a pending bash permission is clicked once (selected, no reply), then twice (reply `once`), and an armed click does not carry over to the next request. A question option is clicked once (cursor only), then twice (submitted). (`screens_mouse::a_single_click_never_answers_a_permission`, `screens_mouse::a_question_is_answered_by_a_second_click`.)
- [x] 1.5 A terminal click reaches `on_mouse` through `runner::terminal_event`, and the drawn palette's row is selected. (`runner::mouse_tests::a_click_from_the_terminal_selects_a_palette_row`.)

## 2. File explorer

- [x] 2.1 Add the `explorer_focus` binding (default `tab`) to `keys.rs`, the chips and `/help`. `preview_focused` now means "keys go to the preview" at every width. The view replaces the tree only below `SIDE_BY_SIDE`, and the focused pane's header title is drawn in `accent`. (`screens_explorer::tab_focuses_the_preview_and_esc_returns_to_the_tree`, snapshot at 120 columns.)
- [x] 2.2 Tree rows are `Row { list: Explorer, act: First }` (select, then Enter through `open_row`). Clicks on the tree pane and the preview pane focus them, the header `rendered`/`raw` chip is `Key(m)`, and the footer chips are `Key(<bound key>)`. Test on the production fixture: click `crates/` (it unfolds), click `README.md` (the preview opens), double click a directory (it unfolds once), click `.env` (the permission request is raised and no content is sent), click the chip (it switches to `raw`), click the `esc close` chip (the explorer closes). (`screens_explorer::clicks_unfold_open_and_toggle`, `screens_explorer::a_click_on_an_ask_file_raises_the_permission_request`.)
- [x] 2.3 Pointer-aware wheel. A notch over the preview scrolls it by 3 lines and leaves the tree selection, and a notch over the tree moves the selection. (`screens_explorer::the_wheel_scrolls_the_pane_under_the_pointer`.)

## 3. Lists, panels, sidebar and transcript

- [x] 3.1 The generic picker (Session, model, mode, `/agent`, `/tasks`, skills, plugins, loops, goals, login, admissions), the palette and the theme switcher register `Row { act: Second }`. Tests: the model picker switches on the second click, `/tasks` opens a log on the second click, and `/agent` switches thread. The theme switcher previews on the first click, keeps on the second and is not reverted by an outside click. (`screens_mouse::picker_rows_select_then_activate`, `screens_mouse::tasks_and_agent_rows_activate_on_a_second_click`, `screens_themes::a_click_previews_and_a_second_keeps_the_theme`.)
- [x] 3.2 Full-screen panels:
  - Workflow monitor run and agent rows (`screens_workflows::a_second_click_opens_the_run_view`)
  - `/messages`, `/team` and `/tree` rows, with `/tree` keeping its idle check (`screens_mouse::messages_team_and_tree_rows_activate_on_a_second_click`)
  - the hook views, which draw no rows to pick, take no clicks (`screens_mouse::hook_lists_take_no_row_clicks`)
- [x] 3.3 Settings: tabs are `Key('1'..'4')`, and Config rows are `Row { act: Second }`. Clicking `Usage` switches the tab, and clicking `timestamps` twice cycles and saves the value. (`screens_settings::clicks_switch_tabs_and_cycle_a_config_row`.)
- [x] 3.4 Sidebar: headers are `Row { act: First }` (focus, then `sidebar_select`), and other rows are `Row { act: Second }`. A click on the transcript or the composer calls `leave_sidebar`, and the wheel over the sidebar does nothing. (`screens_sidebar::clicking_a_header_folds_it_and_the_composer_takes_focus_back`, `mouse::tests::the_wheel_over_the_sidebar_does_nothing`.)
- [x] 3.5 Transcript: the hidden-lines row of a collapsed tool card registers the `tool_details` key, and the `thinking` row registers the `reasoning_toggle` key. Neither registers while its action is unbound. (`screens_mouse::clicking_a_collapsed_tool_output_expands_it`.)

- [x] 4.3 Acceptance on the real binary (2026-10-24): a scripted local OpenAI-compatible provider, `cyber serve --register` under a temporary home, and `cyber -r demo` in a 120x36 pty driven with SGR mouse bytes. `/files`: a click unfolds and folds `src/`, a click on `README.md` opens the preview, the wheel over the preview scrolls it and the wheel over the tree moves the selection. Ctrl+P: the first click selects `Settings: Usage`, the second runs it. `/settings`: a click opens Config, two clicks on `mouse` save `off` and the TUI writes `?1000l` and then ignores injected wheel bytes; a relaunch with `mouse` saved off writes no `?1000h` and ignores clicks.
