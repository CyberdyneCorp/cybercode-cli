## Context

Before this change, `context.rs::instructions()` built its candidate list inline: the global `AGENTS.md`, then for each directory from the project root to the Location, `AGENTS.md` (or `CLAUDE.md` when there is no `AGENTS.md` and `compat.claude` is on) and `CONTEXT.md`. It read each file with no deduplication, imports, override or truncation. Nothing else in the workspace listed these names except the import detector (`cyber-core/src/import/discovery.rs`), which reports other tools' files and is out of scope. Nested on-read discovery and the doctor listing did not exist.

## Decisions

### One ordered list, three consumers
`runtime/instructions.rs` owns `DIRECTORY_FILES = [AGENTS.md, CLAUDE.md, CONTEXT.md, CYBER.md]`, `GLOBAL_FILES = [AGENTS.md, CYBER.md]` and `OVERRIDE_FILE`. `directory_files(dir)` applies the per-directory rules. `load_baseline` feeds `core/instructions`, `load_nested` feeds the read reminder, and `cyber doctor` calls `load_baseline` with the same settings the runtime uses. A new name is one array entry.

### `CYBER.md` comes last in its directory
Within a directory, `CYBER.md` comes after `AGENTS.md`/`CLAUDE.md` and `CONTEXT.md`, so Cyber-specific guidance wins ties. More specific directories still come later overall. A root `CYBER.md` therefore precedes `packages/api/AGENTS.md`, which keeps the existing "more specific wins" rule intact.

### `CLAUDE.md` stays a per-directory fallback
`system-context` says "every `AGENTS.md` and, unless disabled, `CLAUDE.md`". `compat-import` says `CLAUDE.md` loads only where a directory has no `AGENTS.md`, and the code and its test follow `compat-import`. We keep the `compat-import` precedence and clarify the `system-context` wording, because loading both would duplicate content in the many repositories that keep the two files in sync. `CLAUDE.md` keeps its slot (second), so the order contract holds either way.

### `AGENTS.override.md` replaces `CYBER.md` too
An override exists to take over a directory's agent guidance completely (the Codex semantics). If `CYBER.md` survived it, a directory could not be fully overridden, and the result would depend on which agent reads it. So `AGENTS.override.md` takes the `AGENTS.md` slot and replaces `AGENTS.md`, `CLAUDE.md` and `CYBER.md`. `CONTEXT.md` describes the directory rather than giving agent instructions, so it still loads.

### Disable switches
`CYBER_DISABLE_CLAUDE_MD` (and the `compat-import` spelling `CYBER_DISABLE_CLAUDE_COMPAT`), as well as `compat.claude = false`, disable only `CLAUDE.md`. `compat.claude` is resolved per Location, from the same merged config (project layers included) for the runtime and for `cyber doctor`: the runtime asks the tool host (`ToolHost::claude_compat`, forwarded by AppHost and pinned by `app_host_forwards_every_tool_host_method`), doctor reads `ctx.config()`, and both go through `cyber_core::config::claude_compat`. Reading it once at startup from the server's default directory made doctor and the Session disagree for any project that set it. `CYBER.md` is native, so they never disable it. `CYBER_DISABLE_PROJECT_CONFIG` skips every project file, including `CYBER.md` and nested discovery. The global files still load. The runtime reads these flags from the server process environment through `InstructionSettings::from_env`, and so does `cyber doctor`.

### Deduplication and imports
Every file, imported ones included, is keyed by its canonical path, so a `CYBER.md` symlinked to `AGENTS.md` loads once. `@path` lines outside code fences are expanded depth first, each as its own `Instructions from:` block after its importer. The depth limit is 5. A target already on the import stack is a cycle: it is skipped with a warning naming both files. A target that was already loaded elsewhere is skipped silently. Unresolved imports are warnings, not failures.

**Fail closed:** a project file, the discovered directory file itself as well as each of its imports, must resolve, canonically, inside the canonical project root. Otherwise it is skipped with a warning, so a checkout cannot pull `~/.ssh/...` or `../other-repo` into the privileged context through `@path` or through a symlinked `CYBER.md`/`AGENTS.md`. A symlink that stays inside the project is followed (`CYBER.md -> AGENTS.md` loads once). Inside the project, the same file must also pass the Location's `read` rules: a symlink or `@path` that stays in the checkout could otherwise pull a local, gitignored secret (`@.env`, `web/CYBER.md -> ../.env`) into the privileged baseline or a nested reminder without the prompt a `read` raises. `InstructionSettings::read_gate` (a `ReadGate`, from `ToolHost::instruction_read_gate`, forwarded by AppHost) evaluates the `read` action for the discovered and the canonical path, each absolute and relative to the Location and to the project root, with the default rules plus the configured ones (`cyber_tools::permissions::instruction_read_gate`; doctor builds the same gate). Only an explicit Allow everywhere loads the file; Ask and Deny skip it with a warning, since a context load has no one to prompt. A Location whose config fails to load gets a gate that refuses every project file, and `ToolHost::claude_compat` answers `Some(false)` instead of reading the default `true` from a `Null` config. Global files are user-owned and may import anywhere, and are not gated. Only regular files are read: the path is checked with `metadata` before opening (opening a FIFO blocks) and again on the open handle, and reading goes through `take(limit + 1)`, so `/dev/zero`, a FIFO or a huge file can neither block nor exhaust the loader. A path that is not a regular file is an error like any unreadable instruction file: the baseline becomes unavailable (the first Turn is blocked and `cyber doctor` names it), and a nested read records a warning.

### Truncation
Each file is cut at `instructions.max_bytes` (32768) on a character boundary, with a `[Truncated: <path> exceeds instructions.max_bytes (N bytes); M bytes omitted]` notice (M from the file's size). The baseline as a whole is bounded too (`DEFAULT_MAX_TOTAL_BYTES`, 131072), because imports could otherwise add any number of 32 KiB files: the file that crosses the total is cut with a total-budget notice, later files are left out with a warning, and imports stop expanding. The file is marked truncated, and a warning is recorded for `cyber doctor`. Imports are parsed from the kept text only. The value is the fixed default for now, because the top-level `instructions` config key is already the array of configured instruction entries. Reading a `max_bytes` from it needs a schema decision (for example `instructions_max_bytes`), which this change does not make.

### Nested discovery is decided at settlement, in the runtime
The per-epoch "already attached" state has to be durable, and it has to reset with the epoch, exactly like path-matched skill reminders. When a built-in `read` runs, the runtime records the target (resolved against the Invocation's Location, with `~/` expanded). Only a successful read loads anything. Before the Session lock is taken, `load_nested` runs on a blocking thread (`spawn_blocking`) for each successful read of the group, and the results are passed into the locked settlement. It does the following:
- canonicalizes the Location and the target;
- walks the directories from the project root down to the target's directory;
- treats every baseline file (and its imports) and every path in `Epoch.reminded_instructions` as already loaded;
- returns the remaining files.

The reminder is placed before any skill reminder and goes through the same `finalize_skill_output` budget, which keeps reminders whole. One reminder carries at most `NESTED_MAX_TOTAL_BYTES` (32768) of text, and files past it are named instead (still recorded, so the work is not repeated). If the reminder still exceeds the tool output budget (a smaller `tool_output`, or a file of many short lines), a pointer listing the paths is tried, and if that fails too the read keeps its own output and records no file, so a later read can attach them. Instruction files never turn a successful read into `Crashed`; only an oversized skill reminder still does, as before. After the commit, attached files fire `InstructionsLoaded` with `load_reason: "nested_read"`, source `core/instructions`, their `file_paths` and the digest of the attached text. The attached canonical paths are stored on `ToolSettled.instruction_reminders` and projected into `Epoch.reminded_instructions`, so a restart or a parallel read in the same group never attaches a file twice, and a new epoch (compaction, provider switch) starts empty. The work happens in `cyber-server` rather than `cyber-tools` because that is where the epoch and the loader live. The only tool-host addition is `claude_compat` (see Disable switches).

### Mid-session edits
Nothing new. `core/instructions` is still one source. An edit to any instruction file changes its value, reconciliation at the next Safe Boundary sends one durable `session.context.updated.1` message, and the epoch's cached prefix stays byte-identical.

### `cyber import` does not write `CYBER.md`
The `claude` importer discovers `CLAUDE.md` files (`cyber-core/src/import/discovery.rs`), but `compat-import` gives them no write mapping: read-time compatibility already loads them in place. Offering `CYBER.md` as a target would copy the content into a file that loads in addition to `CLAUDE.md` (the compat switches never disable `CYBER.md`), so every rule would reach the model twice unless the user also deleted the source, which an import must not do. The importer is therefore unchanged, and the guide tells users to move only Cyber-specific guidance into `CYBER.md`. A future opt-in "move" (write `CYBER.md`, then rename or delete `CLAUDE.md` after review) would need its own `compat-import` requirement.

### `/init` is unchanged
`skills-commands` specifies `/init` as generating or refreshing `AGENTS.md`, the file every agent reads, and the command is not implemented yet. Pointing it at `CYBER.md` would hide shared guidance from other tools, so this change leaves `/init` alone; generating `CYBER.md` is deferred.

## Risks / Trade-offs

- Truncation, override and imports now apply to existing projects. That is what the spec already required, and doctor shows the effect.
- At each successful `read`, nested discovery re-reads the baseline files to build the dedup set. The reads are bounded and run off the async workers, outside the Session lock. Caching them per epoch is a later optimization.
- A nested reminder budget fixed at 32768 bytes, rather than the exact room the tool output budget leaves, keeps the tool host interface small; the pointer and no-reminder fallbacks cover smaller budgets.
- Reads through `bash`, `grep` or MCP tools do not trigger nested discovery. The spec scopes it to the `read` tool.
